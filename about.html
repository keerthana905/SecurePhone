Smart City Mission: Protect. Locate. Recover.

OVERVIEW

SecurePhone is an intelligent mobile security and anti-theft web platform built for Smart City civic recovery coordination. It empowers citizens to pre-register non-sensitive device metadata, share browser-permitted coordinates on OpenStreetMap, file structured Lost Mode incidents, and correlate missing phones with found-property submissions.

  • Frontend: Semantic HTML5, accessible dark-theme CSS3, Vanilla ES6 JavaScript, Leaflet.js + OpenStreetMap.
  • Backend: Python Flask with session authentication, CSRF protection, rate limiting, and role-based access control.
  • Database: Relational SQLite with foreign key enforcement, audit logs, and recovery status history.

Important Technical Limitations & Honesty

TECHNICAL BOUNDARIES
  • Hardware Power Button Limitation: A standard web application running in a browser sandbox cannot intercept physical hardware power buttons, prevent an actual phone OS from shutting down, or read hardware biometric sensors.
  • Shutdown-Authentication is a Simulation: Our simulator demonstrates the user experience and security logic of pre-shutdown verification using a clearly labelled Demo PIN and mock biometric buttons.
  • Active Browser Geolocation Only: Location sharing requires explicit user permission in an active browser session. A web page cannot track a phone when the browser is closed or after the device is powered off.
  • Zero Collection of Real Unlock Credentials: SecurePhone never asks for or stores real phone-unlock PINs, passwords, patterns, or biometric templates.

Application Security & Privacy Controls

DEFENSE IN DEPTH

1. Authentication & RBAC

Passwords are salted and hashed using Werkzeug PBKDF2/Scrypt. Every protected endpoint verifies both session authentication and strict ownership (`device.user_id == session['user_id']`) or administrator role privileges.

2. Privacy-Preserving Matching

Full IMEI numbers are never stored or exposed publicly—only optional last-4 alphanumeric tags are used for verification. Found-device reports never expose a device owner's private contact details or exact coordinates.

3. CSRF, Rate Limiting & Audit Trail

All state-changing POST/JSON requests enforce cryptographic CSRF token validation. Sensitive routes are protected by per-IP rate limiting, and all critical actions are recorded in an immutable audit log.
